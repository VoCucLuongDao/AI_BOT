# AI_BOT - xiaozhi-esp32 PlatformIO Project

This project has been converted from ESP-IDF framework to PlatformIO ESP32-IDF framework.

## Project Information

- **Original Source**: xiaozhi-esp32_vietnam-develop_vn
- **Framework**: PlatformIO with ESP32-IDF
- **Target Board**: ESP32-S3 N16R8 (16MB Flash + 8MB PSRAM)
- **Platform**: espressif32

## Documentation

- `docs/HOAT_DONG.md` — runtime architecture: boot flow, device state machine,
  audio pipeline, conversation/MCP/OTA sequence diagrams, task & queue model,
  and a quick debugging lookup table (Vietnamese).

## Project Structure

- `src/` - Main source code (converted from main/ directory)
  - `audio/` - Audio codecs and processing
  - `display/` - Display drivers (LCD, OLED, LVGL)
  - `features/` - Music, video, weather, spectrum features
  - `protocols/` - MQTT and WebSocket protocols
  - `led/` - LED control
  - `boards/` - Board-specific configurations
  - `assets/` - Embedded assets (sounds, locales, web browser)
- `partitions/` - Partition table files
- `scripts/` - Build and asset generation scripts
- `sdkconfig.defaults` - The **only** SDK config file (merged IDF defaults + board options)
- `sdkconfig.esp32-s3-n16r8-idf` - Generated by ESP-IDF; do not edit, do not commit

## Configuration

### ESP32-S3 N16R8 Configuration
- Flash Size: 16MB (`board_build.flash_size = 16MB`)
- PSRAM: Octal SPI at 80MHz (`CONFIG_SPIRAM_MODE_OCT=y`)
- Partition Table: `partitions/v2/16m.csv`
- SDK Config: `sdkconfig.defaults` (single file)
- C++ Standard: C++17
- Compiler Flags: RTTI and Exceptions enabled
- Target board type: `xiaozhi-ai-iot-vietnam-es3n28p-lcd-2.8`
  (`CONFIG_BOARD_TYPE_XIAOZHI_AI_IOT_VIETNAM_ES3N28P_LCD_2_8=y`)

### Board Selection
The project is configured specifically for ESP32-S3 N16R8. Board-specific files are in `src/boards/`.
The PlatformIO board is the generic `esp32-s3-devkitc-1`; everything that makes it an
ES3N28P board (PSRAM, flash size, display/touch, board type) comes from `sdkconfig.defaults`.
PlatformIO therefore prints "ESP32-S3-DevKitC-1-N8 (8 MB QD, No PSRAM)" — that banner is
misleading and can be ignored.

**Changing `sdkconfig.defaults` requires deleting `sdkconfig.esp32-s3-n16r8-idf`**,
otherwise ESP-IDF keeps using the old generated config.

## Embedded Assets (important)

ESP-IDF turns each `EMBED_FILES` / `EMBED_TXTFILES` entry into an assembly stub
`<build_dir>/<file name>.S`. PlatformIO compiles every component's sources through
SCons *before* ninja runs, so those stubs must exist up-front. That is why the lists
in `platformio.ini` exist:

- `board_build.embed_files` — binary assets (`src/CMakeLists.txt` `EMBED_FILES`)
- `board_build.embed_txtfiles` — text assets
  (`managed_components/TienHuyIoT_esp-wifi-connect/CMakeLists.txt` `EMBED_TXTFILES`)

Without them the build fails with `Source '.pio/build/<env>/<name>.S' not found`.

**When adding/removing an embedded asset, update BOTH the component `CMakeLists.txt`
and the matching list in `platformio.ini`.** The locale entries must match
`CONFIG_LANGUAGE_*` in `sdkconfig.defaults` (currently `vi-VN`).

## Build Fixes Applied

1. **RTTI Support**: `CONFIG_COMPILER_CXX_RTTI=y` in `sdkconfig.defaults`
2. **Exception Support**: `CONFIG_COMPILER_CXX_EXCEPTIONS=y` in `sdkconfig.defaults`
3. **ESP32-S3 Target**: Removed redundant `-DCONFIG_IDF_TARGET_ESP32S3=y` flag (ESP-IDF auto-defines it)
4. **Single sdkconfig**: Merged upstream `sdkconfig.defaults` + `sdkconfig.defaults.esp32s3`
   into one root `sdkconfig.defaults` (PlatformIO 6.x does not support
   `board_build.sdkconfig_defaults`; IDF only auto-reads the root `sdkconfig.defaults`)
5. **Embedded assets**: Pre-generate the `.S` stubs via `board_build.embed_files` /
   `board_build.embed_txtfiles` (see "Embedded Assets" above)
6. **Removed invalid options** from `platformio.ini`: `build_cxx_flags`, fake `-DCONFIG_*`
   defines, `-mfix-esp32-psram-cache-issue`, `build_type = debug`
7. **Wake Word Detection**: Simplified `IsAfeWakeWord()` to avoid `dynamic_cast` dependency
8. **Exception Handling**: Fixed `lyric_manager.cc` to use a simple try-catch without exception objects
9. **Language Config**: Pre-build script generates `src/assets/lang_config.h` automatically
10. **C++ Flags**: `-std=gnu++17` for C++17 support
11. **Quiet Kconfig**: `scripts/pre_build.py` exports `ESP_IDF_VERSION` (read from
    `framework-espidf/version.txt`) so `option env="ESP_IDF_VERSION"` in
    `esp_codec_dev/Kconfig` resolves; the stray duplicate
    `config PARTITION_TABLE_CUSTOM_FILENAME` inside the board-type `choice` in
    `src/Kconfig.projbuild` was removed (it duplicated IDF's symbol and produced
    four Kconfig warnings).
12. **Managed-component warnings**: `add_compile_options(-Wno-missing-field-initializers)`
    and `add_compile_options(-Wno-deprecated-declarations)` in the root
    `CMakeLists.txt`. Managed components are regenerated by the component manager,
    so warnings inside them (e.g. `esp_lvgl_port` calling the deprecated
    `esp_lcd_touch_get_coordinates()`) must be silenced at our layer — never by
    patching `managed_components/`.
13. **Warning-free build**: current baseline is `0 warnings, 0 errors`, RAM 18.8 %,
    Flash ~87.3 %. If a new `warning:` appears, find which TU/component emits it
    before adding any `-Wno-*` flag.

## Troubleshooting

### `error: exception handling disabled, use '-fexceptions' to enable`

`sdkconfig.defaults` is missing from the project root, so ESP-IDF regenerates
`sdkconfig.esp32-s3-n16r8-idf` without `CONFIG_COMPILER_CXX_EXCEPTIONS` and
`CONFIG_COMPILER_CXX_RTTI`. Fix:

```powershell
git checkout -- sdkconfig.defaults
Remove-Item sdkconfig.esp32-s3-n16r8-idf -Force
pio run
```

> `include/lv_conf.h` is **not** used by this build: `CONFIG_LV_CONF_SKIP=y` makes
> LVGL ignore it and take every option from Kconfig / `sdkconfig.defaults`. The file
> is kept for reference (and lives in `include/`, which is on the include path) but
> it does not affect the build — editing it changes nothing.

### `warning: "_IO" redefined` (esp_video vs lwIP)

`managed_components/espressif__esp_video/include/linux/ioctl.h` defines
`_IO`/`_IOR`/`_IOW`/`_IOWR` unconditionally, while lwIP's `sockets.h` already
defines them. TUs that include both (e.g. `lvgl_display.cc`) get macro
redefinition warnings. **Do not patch the managed component** — the
push_macro/pop_macro guard lives in our own
`src/display/lvgl_display/jpg/image_to_jpeg.h`.

### `_Null` + `str` TypeError in verbose builds

`pio run -v` is broken for the `firmware.bin` action (see "Known Quirks"); use a
normal `pio run`.

## Known Quirks

- On a clean build a transient ldgen/link error such as
  `libespressif__adc_battery_estimation.a: No such file` can appear; re-running `pio run` succeeds.
- `pio run -v` (verbose) crashes at the very last step with
  `TypeError: unsupported operand type(s) for +: '_Null' and 'str'` while SCons prints the
  `firmware.bin` action (PlatformIO/SCons issue, unrelated to this project).
  Use a normal `pio run` to build the binary; verbose is only useful for reading
  Kconfig/CMake output that normal builds hide.
- Kconfig warnings are printed on stderr by the confgen step, so plain
  `pio run 2>&1 | Out-File` output may hide or mangle them; capture with
  `cmd /c "pio run > log.txt 2>&1"` when debugging Kconfig.
- Firmware flash usage is ~87 % of the 4 MB app partition — remaining headroom is small.
- `scripts/pre_build.py` runs on every build and regenerates `src/assets/lang_config.h`.
  It now restores the old mtime when the generated content is identical, so a
  no-op build stays incremental (a fresh mtime dragged most of the project into a
  ~6 minute rebuild). Delete the header if you ever want to force regeneration.
